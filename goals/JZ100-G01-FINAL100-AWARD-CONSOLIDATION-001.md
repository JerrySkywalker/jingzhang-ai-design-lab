## 8. S01 P0 source model

Create:

`visual/assets/p0-s01-reference.json`

The P0 is a participant-authored pre-feasibility reference, not approval or site design.

### Purpose

One supervised physical AI equipment/model-observation session inside a removable fit-out while ordinary route and ordinary training/work remain intact.

Ordinary rooms remain sufficient for planning, simulation, briefing and post-test review. Spatial admission is justified only when a verified real physical task, task equipment, operator and safety responsibility require an inspectable control/observation/reset edge.

### Envelope

Authoritative:

`E = R_existing + T_verified + B_professional + H_authority + O_observer + M_reset`

A `12 m × 9 m` zero-coordinate rectangle may be used only as `DESIGN_ASSUMPTION` for layout, quantities and jury communication.

Keep task footprint, code/safety buffer, egress, accessibility clearance, height, floor load, anchorage and power null/parametric until professional input.

### Zones

- Z0 ordinary clear route; never queue/storage/test
- Z1 arrival/handoff
- Z2 removable test zone
- Z3 human authority/operator
- Z4 booked observer zone
- Z5 maintenance/reset access
- Z6 variable professional safety/setback buffer

Draw them primarily through the three temporal layers rather than making Z-codes the visual concept.

### Capacity

Participant operational assumption only:

- one active task/device
- five session role positions
- four booked observer positions
- design cap nine
- no walk-in admission
- no standing queue in Z0
- `field_observed_capacity=null`
- `approved_capacity=null`

Stop on absent required role, second task/device, observer overflow, route intrusion, unbriefed Z2 entry or any lower professional limit.

### Staffing

Five per-session role classes:

1. test operator
2. separate human safety authority
3. public/service handoff
4. maintenance/reset role
5. independent observer/reviewer

Do not convert to FTE or named organizations.

### Component schedule

Model eight removable/reusable component groups with function/state/dependency/inspection/fail-closed consequence:

- STATUS/reset frame
- removable perimeter
- floor/interface protection
- power/isolation interface
- physical stop/control kit
- operator/safety console and log
- handoff/observer elements
- reset/storage inventory

### Operation / reset

`external-gate pre-open -> ordinary-baseline verification -> install/inspect -> conditional activation + stop rehearsal -> one controlled task -> fail-closed stop -> human isolation/takeover -> reverse removal -> surface/route restoration -> independent ordinary-baseline verification`

Never claim a reset duration.

Damage, missing component, uncertain isolation or incomplete ordinary baseline => `QUARANTINED`; P0 remains stopped.

### Maintenance

Event-based participant model:

- before deployment
- before session
- after session
- after any stop/fault
- future manufacturer/professional intervals stay null until actual product selection

### Alternatives

Keep visible:

1. NO-BUILD simulation/ordinary room/manual review
2. lower-tech reversible markings/manual cordon/human observation
3. selected removable P0
4. alternate linear side-bay layout

Alternatives 1/2 win unless verified physical need defeats them while preserving ordinary route.

### ROM/OPEX

Only use source-bounded ranges or relative sensitivity.

`CAPEX_ROM = Σ(quantity × dated public unit-rate low/base/high) + installation/inspection allowance + uncertainty reserve`

`OPEX_ROM = role-hours + setup/reset + inspection/certification + storage/transport + utilities/consumables + replacement reserve`

If credible public/source-backed rates are unavailable, use a relative index; do not invent CNY totals.

Expose:

- `market_quotation_count=0`
- `approved_budget=null`
- `funding_commitment=null`

- fire/life safety/egress
