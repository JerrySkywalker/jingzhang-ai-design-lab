# AI Scenarios and Task-to-Space Gate

These cards are mandatory evidence for retaining Candidate 05's conditional AI threshold. Dimensions are typological until a carrier, task and professional survey are verified.

## TTS-01 — bounded model/equipment validation (north)

```text
task = validate a model/device in a controlled, supervised state
state = SETUP → READY → RUNNING → PAUSED/SAFE → REVIEWED → RESET
uncertainty / TTL = authorization, equipment and safety state expire per session; stale state cannot permit operation
minimum information/resource = task owner, consent/authorization, safety envelope, human supervisor, emergency stop, minimum power/data/equipment and reset record
ordinary-space sufficiency = ordinary meeting/work rooms suffice for planning, code review and non-physical simulation
spatial consequence = only a verified physical/equipment test receives separated test envelope, service/reset edge, supervised observation and reversible fit-out
AI-off / fallback = stop automated test; safe shutdown; human inspection; room returns to ordinary workshop/training use
exit = remove equipment/controlled partitions where reversible; preserve ordinary building/public route
```

`NO-BUILD` finding: planning, review, simulation and education use ordinary rooms unless physical/safety evidence proves otherwise.

## TTS-02 — secure collaborative project/data room (middle)

```text
task = temporarily collaborate on a project with controlled data/model access beside ordinary public learning/community use
state = PUBLIC → BOOKED → CONTROLLED SESSION → HUMAN REVIEW → CLEARED → ORDINARY REUSE
uncertainty / TTL = identity/role and data authorization expire at session end; no persistent public eligibility profile
minimum information/resource = project authorization, data classification, named human reviewer, local/offline work option, minimum secure storage/network and deletion/return record
ordinary-space sufficiency = public teaching, discussion, community work and non-sensitive collaboration need no special AI room
spatial consequence = reversible public/controlled partition, separate entry/visibility rule, acoustic/data controls and staffed handover only during sensitive sessions
AI-off / fallback = paper/local material, staffed meeting or ordinary room; secure side closes without closing public route
exit = clear resources and return the whole carrier to ordinary learning/work/community use
```

`NO-BUILD` finding: most learning/community/small-team work remains in ordinary adaptable rooms.

## TTS-03 — staffed adoption/compliance room (south)

```text
task = review a bounded AI product/use case with customer/public-service and compliance implications
state = INTAKE → EVIDENCE READY → HUMAN REVIEW → DEMONSTRATION → DECISION/REWORK → ARCHIVE/EXIT
uncertainty / TTL = claims, policies, permissions and demo data have explicit as-of dates; stale evidence blocks decision
minimum information/resource = public source/claim register, test evidence, qualified human reviewer, privacy/appeal/stop path, ordinary service desk and removable demo kit
ordinary-space sufficiency = general business, legal referral, meeting, service and exhibition use ordinary staffed mixed-use rooms
spatial consequence = a verified carrier may need a controlled review/demo side, staff sightline, queuing/privacy separation and time-bounded operating envelope
AI-off / fallback = human intake/referral, paper/phone and ordinary meeting; no automated decision or loss of service
exit = remove demo system; room remains ordinary professional/community service space
```

`NO-BUILD` finding: general professional/customer service does not require bespoke AI architecture.

## AI-assisted renewal option comparison

This is a planning aid, not the concept mechanism. It may compare source-tagged alternatives and flag uncertainty/conflict. The output is advisory, versioned and human-reviewable. It may never automatically label a building for demolition, open a campus edge or allocate public rights.

## AI double-test receipt

```text
AI_OFF_CITY=PASS
AI_MATTERS=PASS_CONDITIONAL
TASK_TO_SPACE_GATE=PASS_WITH_NO_BUILD_FINDINGS
```

AI matters because verified tasks change selected room envelope, access separation, service/reset, staffing and operating states. The pass becomes fail if formal development treats these as optional tenant fit-outs without a spatial/operating contract.

## Common risk controls

- data minimisation; no general public surveillance;
- clear authorization/TTL and stale-state rejection;
- qualified human review and named stop authority;
- physical/manual/non-digital fallback;
- ordinary public route and service never depend on AI;
- safe removal and ordinary reuse;
- no claim that a carrier/operator/partner currently exists.
