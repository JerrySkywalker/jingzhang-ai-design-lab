## A. 今天真正新增了什么证据

本轮没有再各写一套喜欢的故事，而是让 C01、C02 共用一个 pinned contextual base。由此得到四项可淘汰结果：

1. C01 的 universal re-embodiment station 被模型否决；共享不是默认，七种需求状态中只有错峰 ordinary/weekday 由分布式共享胜出，其余五种由 dedicated 更低。
2. C01 的窄 kernel 首次落为三种不同剖面，并在 AI-off、低采用、峰值、cell 故障、雨热、活动和维护状态下改变前后场、路缘、公共 refuge、物流和分期，因此获得**概念层 Spatial Admission PASS**。
3. C02 的 H3 没有从共同底图中获得正证据；H2/H4+ 也未决，Corridor+N 是最稳健的工作架构。`exactly three` 身份被杀，ordinary-day contract 保留。
4. official 结束时累计前进 95 commits；规则和 geometry 未变。新增竞品进一步占据普通日、维修、失败侧线、共享组件和三核叙事，但未发现完成 C01 全窄链的直接 killer。

## C. C01

### 活下来的 unique kernel

```text
public task
→ observable state / uncertainty / TTL
→ minimum sensing-compute-energy-tool-maintenance bundle
→ four-way shareability
→ isolated allocation + degraded/recovery
→ bounded physical consequence
```

Agent、robot、digital twin、fallback、charging、maintenance、public interface、reversible pilot 等均不再是 originality claim。

### 三张 section

- **Zhongzhiyuan productive backend**：公众前台与普通步行在前；受控 handoff、两处隔离 cell、维修/储存/能源与 specialized backend 在后；排水/景观边先行。
- **AI Origin civic front**：普通 civic/learning room、人工/纸电话服务、无障碍步行、shade/refuge 在前；只容纳 lightweight local cell，重维修远离生活。
- **Dazhongsi metropolitan adoption typology**：普通到达、人工帮助、企业/商业交换、常规装卸先行；临时服务、small recovery、event/AI-off 状态共存。不是精确站点设计。

AI-specific 的是任务导出的隔离域、选择性 cell、受控 handoff 和 failure recovery；loading、storage、staff room、cleaning、maintenance、help counter 多数首先是**普通城市后勤/公共服务空间**。若普通空间足够，不新建 AI 类别。

### 最大 kill argument

专业 plan/section 若证明所有 programme 都可被普通 servicing 吸收、或技术层必然损害步行/公共/蓝绿空间，C01 就应被杀。当前模型也是警告：dedicated 在五个压力 profile 胜出；共享只能条件成立时进入。

### 当前判断

`C01_SPATIAL_ADMISSION=PASS` 仅是 conceptual urban-program PASS。建议 `ADVANCE_WITH_MAJOR_REWRITE`，不等于最终 finalist/winner；下一关必须是城市设计、交通、景观、building survey 与 bounded field observation。
