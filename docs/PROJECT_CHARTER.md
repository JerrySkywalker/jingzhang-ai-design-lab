# Project Charter

## Purpose

Maintain a durable, inspectable design memory for developing a competitive **complete urban-design proposal** for the Centennial Jing-Zhang AI Innovation Belt open call.

## Problem statement

Chat conversations are useful for exploration but are poor long-term project memory. This repository converts discussion into persistent requirements, evidence, candidate concepts, decisions and drafts while keeping the future official-submission fork clean.

## Scope

In scope:

- official requirement interpretation;
- source and benchmark indexing;
- complete urban-design candidate concepts;
- systems-engineering and AI/embodied-intelligence technical deep dives;
- comparative evaluation and owner decisions;
- fieldwork planning and later field-observation records;
- pre-submission drafts and migration notes.

Out of scope:

- pretending this repository is an official planning product;
- mirroring the full competition repository;
- storing private/uncleared data;
- opening the eventual formal submission PR from this repository.

## Success criteria

Before a final concept is selected, the lab should be able to answer:

1. What does the official brief require at each spatial scale?
2. What is fact, provisional geometry, derived evidence, assumption, or concept?
3. How does each candidate provide a complete urban-design response rather than a technology theme?
4. Where is each candidate differentiated from strong existing submissions?
5. Which parts have genuine human/system-engineering contribution?
6. What remains unknown and what evidence could resolve it?
7. What exactly will be migrated into the formal `haidian` submission package?

## Operating model

`official requirements → evidence / benchmark audit → candidate concepts → falsification → owner decision → formal fork → submission iteration`

The repository must preserve rejected reasoning when it could prevent future repetition.
